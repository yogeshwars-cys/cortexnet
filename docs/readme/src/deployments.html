Two ways to run it

The same reads and fade, aimed at whatever runs out first. Every arm keeps the model fixed and changes only the read tool.

On your own hardware

llama.cpp, vLLM or transformers; a laptop GPU or rented H100s and H200s

runs out of

the context window (8k on a 6 GB GPU), KV-cache memory and prefill compute

cortexnet

keeps file text to a third and fades against the window the server reports, so a long session fits; the history stays append-only between fades, so the server's prefix cache keeps working

13/20

0.59x

Muse Glimmer 30B, H100: peak KV cache; 0.42x prefill, same success

0.40x

Llama 4 Maverick, 4x H200: peak context; 0.31x file tokens

On a hosted API

Meta Model API, Baseten, any OpenAI- or Anthropic-compatible endpoint

runs out of

input tokens, billed again on every turn, and the context ceiling on long tasks

cortexnet

rewrites a read only when it is fresh and replays it byte for byte, so the provider's prefix cache keeps matching; an optional rule weighs a round trip against tokens re-read from cache

Where it pays least: short tasks on a prompt-cached API. There a whole file is paid once and re-read at about a tenth of the price, so the extra turns of outline-first reads can cost what the smaller reads save.
