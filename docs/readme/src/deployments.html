Local and external

The same core, aimed at whatever runs out first. Every comparison keeps the model fixed and changes only the read tool.

Local: CortexNET

the engine next to llama.cpp on the same machine; tested on a 6 GB laptop GPU

runs out of

the context window, KV-cache memory and prefill time: 6.14 GB holds 4.4 GB of weights, 1.0 GB of KV cache for 8k and 0.4 GB of compute, so the window stays at 8k

cortexnet

puts about a third of the file text in context and fades against the window the server reports; between fades the history is append-only, so the server's prefix cache keeps working

External: API and cloud

Cortex CLI, the egress proxy or the MCP server; hosted APIs and open weights on cloud GPUs

runs out of

input tokens, billed again on every turn, and the context ceiling on long tasks

cortexnet

rewrites a read only when it is fresh and replays it byte for byte, so the provider's prefix cache keeps matching; an optional rule weighs a round trip against tokens re-read from cache

Where it pays least: short tasks on a prompt-cached API. There a whole file is paid once and re-read at about a tenth of the price, so the extra turns of outline-first reads can cost what the smaller reads save.
